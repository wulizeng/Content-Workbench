# 招商入驻模块 响应式 UI/UX 优化设计

## 背景与目标

对"分销枢纽 - 招商入驻"模块的三个页面进行 UI/UX 优化，使其同时在 PC 端和移动端有扎实的体验：

- `pages/recruit/login.html`（客户注册/登录）
- `pages/recruit/apply.html`（入驻申请表单）
- `pages/recruit/list.html`（申请列表，BD 审核用）

范围允许对信息架构做微调（分步骤、分组、增加状态提示等），但不改变现有业务逻辑（登录校验、草稿存储、审核流转等）。

## 统一断点规范

页面级 `@media` 断点（不修改 `css/style.css` 中现有的全局断点 1400px/1200px/768px）：

- **移动端**：`≤640px`
- **平板**：`641px ~ 1023px`
- **桌面端**：`≥1024px`

移动端表单类页面统一采用 **48px** 最小触控高度（input/select/button）。

## 页面设计

### 1. login.html（客户注册/登录）

**移动端（≤640px）**
- 登录卡片改为撑满宽度（去掉固定 400px），左右留 20px 边距
- 手机号/姓名/验证码输入框高度提升到 48px，字号提升到 15px 便于触控点读
- "获取验证码"按钮在移动端保持在输入框右侧（不换行），但最小宽度调整为不小于 96px，避免误触

**平板/桌面端（≥641px）**
- 保持现有居中卡片布局（400px 宽），维持现状即可，不做改动

### 2. apply.html（入驻申请表单）

**移动端（≤640px）**
- 顶部固定步骤条（sticky top），三步：① 基础信息 → ② 平台账号 → ③ 业绩证明
- 每步一屏，底部固定"上一步/下一步"按钮条（最后一步显示"提交申请"）
- 步骤间切换用 JS 控制 display，不做路由跳转，localStorage 暂存草稿（防止意外刷新丢失已填内容）
- 平台账号的"添加账号"卡片在移动端保持现有堆叠样式，但卡片内 select/input 高度同样提升到 48px
- 业绩截图上传区域触控优化：上传框最小高度 120px，方便点击

**平板（641px~1023px）**
- 不强制分步，但表单分区域展示：基础信息和业绩证明双列（`grid-template-columns: 1fr 1fr`），平台账号区域独占一行
- 宽度上限 720px 居中

**桌面端（≥1024px）**
- 左侧固定步骤导航条（240px 宽，sticky），显示三步及当前进度，可点击跳转到已填过的步骤（未填的步骤禁用跳转，强制顺序）
- 右侧表单区自适应宽度，基础信息用两列栅格（品牌+主推产品同行），平台账号列表保持竖向堆叠但卡片本身可以变宽、卡片内字段横向排（平台select + 账号input 同行）
- 校验错误：桌面端右侧表单区域宽度够，错误提示保持在字段下方即可，不用浮层
- "修改重提"/"申请详情"只读态：桌面端保持现有锁定横幅（locked-banner）+ disabled 样式即可，不需要额外改动

编辑模式（`mode=edit`）在移动端进入分步布局时，需要一次性把已有数据分别填入三步中——实施时处理，不影响设计层面的信息架构。

### 3. list.html（申请列表，BD 审核用）

**桌面端（≥1024px）**
- 保留现有表格骨架，增强细节：
  - 表头 `sticky top: 0`，长列表滚动时表头不丢
  - 姓名/手机号/GMV/状态 为核心列常驻；平台账号摘要在窄桌面（1024~1279px）时可换行显示，不单独隐藏
  - 操作列"查看"改为图标+文字（放大镜图标），增加 hover 态提示
  - 搜索区域（search-area）不变，现有筛选项（手机号/平台/状态）保留

**平板（641px~1023px）**
- 表格保留，但隐藏次要列：创建时间列收进"状态"列下方以小字展示（同格叠加），平台账号摘要列宽度压缩，超长用省略号+hover 提示完整内容
- 搜索区域三个筛选项从横排改为可折叠（默认收起，点击"筛选"展开），节省纵向空间

**移动端（≤640px）**
- 表格整体改为卡片流：每条申请一张卡片
  - 卡片头：姓名 + 状态徽章（右对齐）
  - 卡片体：手机号、GMV、平台账号摘要（chip 形式，与 mine.html 风格一致）
  - 卡片底：提交时间（小字灰色）+ "查看详情"按钮（右对齐，跳转 detail.html）
- 搜索区域改为顶部悬浮"筛选"按钮，点击弹出底部抽屉（bottom sheet），包含手机号/平台/状态三个筛选项+查询/重置按钮
- 分页组件在移动端简化为"加载更多"按钮，替代传统页码翻页

**detail.html（详情页）联动**
- 当前 detail.html 是独立页面（非弹窗），在移动端下保持独立页面即可（不改造成 PC 端那种 modal 蒙层弹窗方式，触屏上全屏页面体验更好）
- detail.html 内的 `.detail-grid`（两列）在移动端改为单列堆叠，桌面端保留两列

## 不在本次范围内

- 不修改 `css/style.css` 的全局断点变量
- 不改变登录校验逻辑、草稿存储机制、审核状态流转逻辑
- 不涉及 mine.html 的响应式改造（未被列入本次优化范围）
- 不涉及后端/接口层，仍基于 `localStorage` mock 数据

## 测试计划

- 手动在浏览器 DevTools 中分别模拟移动端（375px 宽）、平板（768px 宽）、桌面端（1440px 宽）三档视口，逐页验证：
  - login.html：输入框触控高度、验证码按钮不换行
  - apply.html：移动端分步切换与草稿暂存、平板双列分区、桌面端步骤导航跳转限制
  - list.html：桌面端表头 sticky、平板列压缩、移动端卡片流与底部抽屉筛选、加载更多
- 验证 detail.html 在窄屏下 `.detail-grid` 单列堆叠，宽屏下两列不变
