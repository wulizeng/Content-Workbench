# 客户合作详情页审核按钮 设计文档

日期：2026-09-07
状态：已实施（提交 7d800d8，本文档为事后补记，设计经用户确认）
关联页面：pages/recruit/detail.html（客户合作管理 · 只读详情页）

## 背景与目标

客户合作管理列表已改接入驻申请数据源。运营/管理员在详情页查看申请后，需要一个业务审核入口，对"已提交"的申请执行审核通过操作。此前审核入口仅存在于 pages/store-engine/manage.html（入驻申请管理侧）。

## 方案选择

- 方案 A（采纳）：详情页头部"审核通过"按钮 + 页面内弹窗确认，调用既有 `Store.review`。
- 方案 B（否决）：跳转 manage.html 完成审核——打断查看上下文，多一次跳转。

## 交互设计

1. **入口**：页头标题行右侧主按钮「审核通过」（`#btnReview`），默认按显隐门槛控制。
2. **显隐门槛**（与 manage.html 既有约定一致）：
   - 角色：`user.role === 'operator'` 或 `user.role === 'admin'`（`canReview()`）
   - 状态：`app.status === 'submitted'`
   - 不满足任一条件则按钮隐藏；unsubmit/reviewed 状态均不可审核。
3. **审核弹窗**（`#reviewModal`）：展示申请摘要（编号/客户名称/模式，`#reviewAppInfo`）+ 审核备注 textarea（`#reviewRemark`，**选填**，maxlength 200）+ 取消/确认按钮。
4. **仅审核通过**：无驳回分支（用户确认：驳回流程后续需求再扩展）。
5. **确认逻辑**：`Store.review(appId, remark, operatorName())`；`operatorName()` = user.name || user.phone 回退。失败时 toast 显示 store 返回错误。
6. **成功后**：关闭弹窗、toast「审核通过」、原地更新 `app = Store.get(appId)` 并 `render()` 刷新——状态徽标变"已审核"、审核时间/审核备注出现、版本历史追加审核记录、按钮按门槛隐藏。
7. **关闭**：取消按钮 / 遮罩点击 / Esc 均关闭弹窗，不清空已输入备注以外的状态（备注每次打开时重置）。

## 数据与权限

- 零 store 改动：完全复用 `Store.review`（状态流转 submitted → reviewed、写版本历史、记 reviewedAt/reviewReason 均为既有行为）。
- 登录态：页面已有 `Auth.requireAuth()`；角色读取 `Auth.getCurrentUser()`。

## 测试

页面级测试 1 个（tests/onboarding.test.js：'cooperation detail page exposes review action for operator roles'）：断言四个元素 id、`Store.review(` 调用、operator/admin 角色门槛、submitted 状态门槛、内联脚本可编译。

## 约束遵循

- ES5 风格（var/function）
- 弹窗样式复用页面既有 `.review-*` 内联 CSS 与共享 status-tag/toast 约定
- 不修改 js/onboarding-store.js、js/auth.js
