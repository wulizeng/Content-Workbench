# 营业执照上传与模拟识别回填 设计文档

日期：2026-09-06
状态：已实施（提交 6c575b4，本文档为事后补记，设计三节均经用户逐节确认）
关联页面：pages/store-engine/manage.html（客户入驻申请编辑页 · 财务信息模块）

## 背景与目标

运营/商务在填写入驻申请财务信息时，企业全称、税务登记号等字段需手工对照营业执照录入，易错且费时。本功能在财务信息模块顶部提供营业执照上传入口，上传后"自动识别"并回填模块相关字段。

原型阶段无 OCR 服务，识别为**模拟实现**：1.5 秒延时 + 内置演示数据池，用于演示交互链路。

## 方案选择

- 方案 A（采纳）：财务信息面板顶部独立上传区块，识别成功后直接回填表单字段并触发既有自动保存链路。
- 方案 B（否决）：独立识别弹窗分步确认——多一层交互，原型阶段无必要。

## 交互设计

1. **上传入口**：财务信息面板顶部（面板标题之下、字段之上）虚线框区块，含"上传营业执照"按钮、文件名/状态提示、预览缩略图位。
2. **文件约束**：仅 JPG/PNG，≤5MB；不符时 toast 报错，不进入识别流程。
3. **识别状态**：选择文件后显示缩略图（objectURL，会话内预览，不落盘、不写入 localStorage）+「识别中…」状态；1.5s 后变为「已识别」并回填。
4. **回填字段**（仅执照真实字段）：
   - 企业全称 → `f_finance_fullName`
   - 税务登记号 → `f_finance_taxNo`
   - 企业所在地 → 境内（`f_finance_region_domestic`）
5. **覆盖策略**：直接覆盖已有值，回填后 toast 提示"已根据营业执照回填 N 个字段"；用户可再手工修改。
6. **联动既有机制**：回填通过设置 input/radio 值后调用 `clearError`、`toggleConditionalFields`、`markDirty`，走既有自动保存与版本历史链路（显式保存时变更记录自然包含回填字段）。
7. **只读态**：`applyReadOnly` 时整个上传区块隐藏（forceViewOnly 或 status === 'reviewed'）。

## 模拟识别逻辑

`LICENSE_DEMO_DATA` 内置 3 组演示数据（不同企业全称/税务登记号），每次识别**随机取一组**——避免多次演示时企业全称+模式+品牌唯一性校验冲突。识别函数延时 1500ms 后回调回填。

## 状态管理

- `resetLicenseState()`：进入表单视图（openFormView）时清空预览、状态文案、已选文件。
- 预览 objectURL 仅存内存变量，页面刷新即失效；申请数据本身不含图片。

## 测试

页面级测试 1 个（tests/onboarding.test.js：'manage page finance panel exposes license upload with mock recognition'）：断言上传区块四个元素 id、入口/状态文案、演示数据池 3 组、三个回填目标字段 id、内联脚本可编译。

## 约束遵循

- ES5 风格（var/function，无箭头函数/模板字符串）
- 不修改 js/onboarding-store.js（回填走既有 saveDraft 链路）
- 不新增页面文件、不引入外部依赖
