# 客户合作管理：列表与详情改接客户入驻申请数据源

日期：2026-09-04
状态：已确认（用户逐节批准）

## 背景与目标

「客户合作管理」页面（`pages/recruit/list.html`，详情页 `pages/recruit/detail.html`）目前读取旧的
`recruit_applications` localStorage 数据（入驻意向审核模型：手机号 / 业务类型 / GMV / 业绩截图等）。

本次改造将列表与详情的数据来源统一切换为「客户入驻申请」（`js/onboarding-store.js`，
localStorage key `onboarding_applications`，加密存储），并按新的字段规范重排列表。
同时彻底清理旧 `recruit_applications` 数据链路及其专属页面。

## 需求要点（用户确认）

1. 列表字段顺序：**序号 | 客户名称（取企业全称）| 入驻类型 | 入驻模式 | 入驻平台 | 对接商务 | 创建时间 | 创建人 | 更新人 | 更新时间 | 状态 | 操作**
2. 入驻类型：由入驻模式归类推导（数据源无独立字段）
   - `DP` → `DP`
   - `客户KOC` / `联营KOC` / `素人KOC` → `KOC`
   - `达播达人` / `达播机构` → `达播`
   - 未知 → `-`
3. 对接商务：入驻申请新增字段 `bdContact`，在申请表单基本信息区展示与编辑（已审核前可改）
4. 创建人 = 申请人姓名（`ownerName`，回退 `ownerPhone`）；更新人 = 最后一条版本记录的 `operator`（无版本记录时回退创建人）
5. 数据范围：列表仅展示 `已提交（submitted）+ 已审核（reviewed）` 的申请；按 `updatedAt` 倒序
6. 详情页：重写 `pages/recruit/detail.html` 为入驻申请的只读详情（不复用 manage.html 表单页）
7. 旧 `recruit_applications` 数据链路直接清理（含删除项目规划旧页）

## 方案选择

- **方案 A（采用）**：页面直接引入 `js/onboarding-store.js` 读取数据，展示层做字段映射；对接商务作为申请顶层新字段，配套新增 `Store.updateBdContact()`；入驻类型推导函数放进 store 作为唯一映射来源。改动最小、数据单一来源。
- 方案 B（弃）：单独适配层模块 `cooperation-view.js` —— 项目无先例，映射逻辑简单，收益有限。
- 方案 C（弃）：审核后复制到独立存储 —— 双份数据同步问题，过度设计。

## 设计

### 1. 数据层：`js/onboarding-store.js`

1. `createDraft()`：新申请顶层增加 `bdContact: ''`（对接商务，字符串，最长 50 字由页面侧约束）。
2. 新增方法 `updateBdContact(id, bdContact, operator)`：
   - 申请不存在 → `{ ok: false, error: '申请不存在' }`
   - `status === reviewed` → `{ ok: false, error: '当前状态（已审核）不允许修改对接商务' }`
   - 值有变化：更新 `app.bdContact` 与 `updatedAt`，`pushVersion(app, '更新对接商务', ['对接商务：旧值 → 新值'], operator)`；值未变化：不落版本记录，仅返回 `{ ok: true, app }`
   - 成功返回 `{ ok: true, app: clone(app) }`
3. 新增辅助函数并导出 `typeOfMode(mode)`：按上文规则返回 `'DP' | 'KOC' | '达播'`，未知返回 `'-'`。
4. 旧数据兼容：读取到的申请若无 `bdContact` 字段，展示层按空字符串处理；不做数据迁移。

### 2. 客户入驻申请页：`pages/store-engine/manage.html`

- 基本信息卡片（`ob-basic-info`）新增一行：标签「对接商务」+ 值。
- 未审核（`status !== reviewed`）时，值旁显示「修改」chip（复用 `ob-chip-edit` 样式）；点击弹出小弹窗（复用 `ob-modal` 样式）：单个文本输入框（最长 50 字）+ 取消 / 保存；保存调用 `Store.updateBdContact()`，成功后刷新基本信息行并 toast 提示。
- 已审核后不显示修改入口，仅展示文本。

### 3. 客户合作管理列表：`pages/recruit/list.html`（重写）

- 标题与面包屑改为「客户合作管理」。
- 数据：`Store.list()` → 过滤 `status ∈ {submitted, reviewed}` → 按 `updatedAt` 倒序。
- 桌面表格列（顺序固定）：序号 | 客户名称 | 入驻类型 | 入驻模式 | 入驻平台 | 对接商务 | 创建时间 | 创建人 | 更新人 | 更新时间 | 状态 | 操作（查看）。
  - 客户名称 = `form.finance.fullName`，空显示 `-`
  - 入驻模式 = `modeByValue(mode).label`
  - 入驻平台 = `platforms.join('、')`，空显示 `-`
  - 对接商务 = `bdContact`，空显示 `-`
  - 状态 = `statusLabel(status)`（实际仅出现 已提交 / 已审核）
- 筛选区：客户名称（关键词模糊匹配）、入驻类型（全部 / DP / KOC / 达播）、入驻平台（下拉，选项取 `Store.PLATFORMS`）、状态（已提交 / 已审核）。桌面端保持现有折叠筛选条交互，移动端保持底部抽屉筛选交互。
- 移动端卡片：头部 = 客户名称 + 状态徽标；正文 = 入驻类型 / 入驻模式 / 入驻平台 / 对接商务 / 创建人 / 更新时间；底部「查看详情」按钮。
- 操作列「查看」→ `detail.html?id=<申请编号>`（沿用 `<a href>` 页签内打开方式）。
- 空态文案：「暂无已提交的入驻申请」。
- 移除全部旧逻辑：`recruit_applications` 读写、mock 种子数据、`recruit_talents` 达人名映射、GMV / 业务类型 / 业绩截图相关展示。

### 4. 合作详情页：`pages/recruit/detail.html`（重写为只读）

- 通过 `Store.get(id)` 读取；`?id=` 缺失或申请不存在 → 空态提示 + 返回按钮。
- 顶部：返回列表按钮 + 标题「客户合作详情」+ 状态徽标。
- 基本信息卡片：申请编号、客户名称、入驻类型、入驻模式、品牌、入驻平台、对接商务、状态、创建人、创建时间、更新人、更新时间、提交时间、审核时间、审核备注（有值才显示）。
- 四个表单模块只读展示（按 `Store.STEPS` / `FIELD_DEFS` 渲染）：
  - 企业业务能力：企业介绍 / 经营规模 / 合作品牌信息 / 付费流量运营案例 / 内容打造案例
  - 企业负责人：负责人联系方式 / 收件地址
  - 项目规划：年度目标 / 账号规划 / 团队配置 / 短视频内容策略 / 投放策略 / 场地设备计划 / 1-12 月月度分解目标
  - 财务信息：企业所在地（境内/境外及境外街道）/ 企业全称 / 企业简称 / 税务登记号 / 银行名称 / 开户省 / 开户市 / 开户行 / 纳税人类别 / 银行账户持有人 / 收款账号
  - 视觉沿用 manage.html 只读面板风格（灰底 + 锁形图标标题）
- 底部版本历史表格：版本号 | 时间 | 操作人 | 动作 | 变更字段。
- 保留页尾设备预览切换脚本（与其他页面一致）。
